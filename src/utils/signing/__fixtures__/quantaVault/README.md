# QuantaVault review vectors

Source: [DigitalGuards/QuantaVault](https://github.com/DigitalGuards/QuantaVault/tree/926c02470b6cde621a66e9ce7b1888b706752d58), commit `926c02470b6cde621a66e9ce7b1888b706752d58`.

- `multi-send.json`, `proposals.json`, and `timelock.json` reproduce the corresponding `test/fixtures` files.
- `typed-data-v2.json` and `vault-approvals.json` retain the scheme vectors and their metadata. Signature material is outside the review decoder's scope.
- `nested-vaults.json` retains the vault addresses, typed message, and digests. `timelock-vault.json` retains the target addresses and scheduled operations.
- `selectors.json` records function names, input fields, signatures, and selectors from `build/hyperion/legacy-optimized` after `npm run compile`, using the source's pinned compiler. The RegistrarStub fixture was compiled with the same compiler for `acceptOwnership`. QRC-20 and generic ownership selectors also use this wallet's `src/abi/CustomERC20ABI.ts` at `d5da2031b203f72bbe481cadc8b11da4499b0740`.
- `calldata.json` was generated by the pinned QuantaVault SDK's `encodeQrvmCall` and `buildMultiSend` for every supported selector. It covers full-width addresses, exact amounts, bytes padding, dynamic arrays, nested ownership calls, and a DelegateCall batch entry. Test expectations use the SDK input values alongside its encoded bytes.
- `review-cases.json` adds transaction overrides to the named base signing vectors. Calldata comes from the same pinned SDK's `encodeQrvmCall` and `buildMultiSendCallOnly`. Reference digests use an independent Node SHAKE256 implementation of the published protocol type strings, checked against both base vectors. The invalid-operation case changes the signed operation to 2 after encoding valid calldata, since the SDK builder rejects that operation.
- Review cases cover zero-target batch entries under Call and DelegateCall for both VaultTx and VaultApproval, scheduled `updateDelay(0)`, `revokeRole` of the zero address, maximum uint256 token approval, an invalid operation with valid calldata, expired validity including zero, and nonzero txGas. Expiry tests use the fixed `reviewTime` timestamp. Unit tests preserve each reference digest; component tests cover effective targets, decoded fields, translated warnings and nonblocking approval behavior.

The decoder uses 64-byte QRVM words. Packed batches use a 193-byte header. ABI integers retain their declared widths. Decoding expands one level of enclosed calls; deeper calls retain their bytes and a warning. Selector recognition describes calldata and does not authenticate the target contract.

The public application-origin list and chain-specific MultiSendCallOnly addresses live in `src/config/quantaVault.ts`. An empty deployment map preserves the DelegateCall warning on every chain. Add an address only after verifying the deployment. Origin metadata remains self-reported even for a listed application.

The wallet currently exposes forward QNS resolution. This review uses the existing full-address component; no reverse lookup API is available at the source revision.

Contract ABI identifiers and role identifiers are protocol data. Review labels and warnings are translated in all shipped locales.
