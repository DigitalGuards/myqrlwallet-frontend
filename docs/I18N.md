# Wallet languages: slices 1 through 6

The renderer supports English, Deutsch, Español, Русский and 简体中文. The language row lives in Settings and applies immediately. Browser detection uses the first supported entry in `navigator.languages`: `de-*`, `es-*`, `ru-*`, and `zh-CN`, `zh-Hans-*` or `zh-SG`; English is the fallback. Traditional Chinese and unspecified `zh` fall back to English. The detected choice is saved on the first visit. Explicit choices take priority on future visits.

## Design

- `src/i18n/index.ts` initializes i18next with English, loads one language chunk on demand, handles overlapping requests and updates `<html lang>`. Rendering begins immediately with bundled English. A failed download or a three-second timeout leaves English active, and the saved choice remains available for the next attempt. A catalog arriving after the deadline cannot change the active language. Production retries use a fresh query on the same build-owned chunk URL, because browsers cache failed module downloads by URL. `catalogUrls.ts` receives those URLs from the build; the self-contained embedded build retains its bundled imports. Selecting the language again requests the catalog without reloading the wallet. English supplies missing keys.
- `src/i18n/i18next.d.ts` derives key types from the English JSON resources and enables `strictKeyChecks`. Misspelled keys fail TypeScript even with a default value. Each namespace is a UI area.
- `src/locales/<language>/*.json` holds the catalogs; each language's `index.ts` groups its namespaces for the lazy import. See [the glossary](../src/locales/GLOSSARY.md) for terminology and security copy requirements.
- `src/i18n/useLanguagePreference.ts` restores the setting and watches settings events in this document and other tabs. Language events are separate from wallet settings events.
- `src/i18n/preference.ts` stores the selected code as JSON in the profile-specific `WALLET_LANGUAGE` key. It migrates an earlier `WALLET_SETTINGS.language` field without modifying that record or its timestamp. Wallet settings retain their original expiration. Unknown codes, objects, null, numbers and malformed JSON become English. Browser detection runs only when no language is stored.
- `LanguageSettings.tsx` exposes the selector on the wallet's own Settings page. Navigation retains the mobile `OPEN_NATIVE_SETTINGS` message and desktop `openDesktopSettings` call. Native windows and their copy belong to the wrapper repositories.
- Stored UI errors and validation messages use keys, so displayed errors follow language changes. Counts use i18next cardinal plurals and whole sentences. Catalogs share the union of `one`, `few`, `many` and `other` forms to give Russian its full forms while maintaining exact key parity. Numbers, dates and balances keep their existing formatters.

Web and desktop builds initially carry English and fetch another language only when needed. The embedded build's existing self-contained, offline document includes every language in the app artifact; language activation still happens on demand. It never downloads executable locale chunks from the hosted wallet.

## Adding another area

1. Move complete messages into the appropriate English namespace. Add the same keys to all four translations. Add a namespace to the language manifests and `namespaces` if needed.
2. Use `useTranslation` in the component and translate at render time. Keep stable keys in state and static navigation models. Use `count` for plurals, interpolation for data, and `Trans` for embedded React elements. Preserve addresses and token metadata as data.
3. Extend `src/i18n/coverage.json` with the converted directory or file. Its JSX guard includes text, display attributes, inline expressions and table headings. Newly added files inside a converted directory are covered automatically. Product terms and punctuation are the only literal text exceptions.
4. Run `npm test -- --runInBand src/i18n`, `npm run typecheck`, the normal CI gates and `npm run smoke:i18n` after building. Catalog tests enforce exact keys, placeholders and component tags, and reject keys without production code references. Test code, comments and translator notes cannot keep an unused key alive. The type test compiles invalid calls to prove missing keys fail.

`npm run smoke:i18n` opens the production build at 360 px with synthetic account inventory and stubbed network responses. It checks language changes without reload, persistence, lazy language loading, unresolved interpolation, browser errors and control overflow. Screenshots and `layout-results.json` go to the temporary directory's `fe-i18n` folder, configurable through `I18N_SCREENSHOT_DIR`. These checks cover renderer behavior; device and native-window qualification remain separate.

## Translator context

[`src/locales/en/_notes.json`](../src/locales/en/_notes.json) is an importable JSON sidecar of translator descriptions. Each property is a `namespace:key` identifier and its string value is the translator comment. For a translation platform, import the fourteen namespace JSON files as messages and map the sidecar values to each key's description/comment field. Apply a logical plural key's comment to all of its `_one`, `_few`, `_many` and `_other` entries. The sidecar is excluded from runtime resources and namespace parity checks; its keys are validated against the English catalogs.

Notes explain ambiguous actions, security consequences, interpolation data and component tags. Add notes when introducing an ambiguous term or security-relevant message. Preserve `{{reason}}` verbatim as service error data, preserve `{{url}}` as the supplied store URL, and retain the `<account>` element inside the export sentence. English intentionally retains raw SDK pairing statuses; unknown runtime statuses and errors remain visible. The original Zod auto-lock validation text is preserved.

### Native shell language contract

`useLanguagePreference` subscribes before restoring the preference. After startup resolution, including English fallback following a failed or timed-out catalog, it sends the active language once and sends again on each distinct resolved change. It does not send the temporary bundled English language while a selected catalog is loading. Repeated same-language events and React StrictMode effect replay do not duplicate the signal. Superseded catalog completions cannot signal an obsolete choice. Cross-tab preference changes use the same path.

The supported language values are exactly `en`, `de`, `es`, `ru` and `zh-CN`:

- Mobile embedded web, when `isInNativeApp()` is true: `sendToNative("LANGUAGE_CHANGED", { language })`. The existing bridge envelope and document binding are preserved: the sender adds `documentId` inside the payload, as with other bridge messages. `WebToNativeMessageType` and `NativeLanguagePayload` in `src/utils/nativeApp.ts` document the contract.
- Desktop: when `typeof window.qrlWallet.setLanguage === "function"`, call `window.qrlWallet.setLanguage(language)`. `QrlWalletBridge` declares the optional method, returning void or a promise of void. Older desktop builds without a callable method are left alone.
- Web: no native message or desktop call is sent.

Shell notification failures are logged and do not undo a resolved renderer language. This contract supplies a language preference to the wrapper; native-window translations and their application belong to the wrapper repositories.
